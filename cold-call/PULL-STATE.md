### The six mechanics: what is in (for the levers agent). All knobs are `CFG.pull.*` in `games/coldcall-engine.js`; the values are PROVISIONAL, the levers agent sets them. Tests pin their own numbers (`tests/lib-pull-pin.js`), so changing the values breaks nothing.
1. LEAD LIST + THE CALLBACK: `list` (size), `fill {dead,win,bonus}` (leads added per paid spin by outcome), `callback {kind}` ('bonus1' | 'bonus2'), `carryOver`. A full list arms a FREE bonus (cost 0, never fills the list, no pot slice). Callback bet = the exact lead-weighted average bet rounded to 10 cents, clamped [10, 2500] (any multiple of 10, NOT a bet level). Daily leads are worked at `min(bet, daily.stakeCap)`.
2. LEADS GO COLD: `cold {afterMs, stepMs, batch, floor}`. Idle time leaks leads and kills warm squares. Result carries `pull.leaked` / `pull.warmDied`.
3. WARM SQUARES: `warm {chance, cap}`. Persist to the next spin ONLY at the same bet (`state.warmBet`); at another bet they are dropped (`pull.warmDropped`).
4. HONEST GHOST ("would have closed"): `ghost {on, maxWinTenths, minTenths}`; `feed {minWinX}` is the friends-feed threshold.
5. ONE DECISION PER BONUS: `pick {on, minLeads, mult}` (PICK the square) and `more {on, mult, rtp, minTenths}` (ONE MORE CALL gamble, gated so the 10,000x cap holds); `decision {timeoutMs}`. Pending round per account + currency, default on timeout / owner disconnect / autoplay; a round open at server restart is voided and refunded once. Each open round snapshots the knobs at spin time (`rec.cfg`).
6. SHARED OFFICE POT + FRIENDS FEED: `pot {feedBps, oneInPerDollar, seed, minBal, maxPayX}` (`oneInPerDollar <= 0` = never). Pot is settled with the round, not at spin. Friends feed events via `feed`.
- DAILY APPOINTMENT: `daily {base, perStreak, streakMax, stakeCap}`, once per Chicago day per currency, free leads, not claimed by a buy.
- `pull.on` is the master switch. Sim: `node games/coldcall-sim.js --pull` and `--bonus` (see `PULL-SIM-NOTES.md`, now in real cents, state carried across sessions, `--bet-switch`).

### Server bits for the wave-2 UI (commit 9a59e6f on `coldcall-pull`; PULL-UI.md section 0, all three built, no UI change needed)
- `g:coldcall:ready {roundId}` -> every socket of the account gets `g:coldcall:timer {roundId, timeoutMs, expiresAt}`. The first `ready` of a decision re-arms the timer to a full `timeoutMs` from now; a repeat for the same decision replies the SAME `expiresAt` and changes nothing. PICK and ONE MORE CALL each get one re-arm. A re-arm never reaches past `armedAt + 2 x timeoutMs` (a `ready` after that point is silently ignored; the running timer decides). Errors use the `decide` shape: `no_round` (unknown, settled, malformed roundId), `forbidden` (not your round), `rate` (150 ms per account, own limiter, separate from spin's; a refused `ready` does not use up the re-arm, so a UI double-send inside 150 ms gets `rate` and should just ignore it). The UI should treat `timer` as authoritative for the countdown and keep its own 1 s fallback.
- `g:coldcall:state`: `pull.rules` = JSON clone of the live `CFG.pull` at that moment, the WHOLE object (also `pot`, `feed`, `decision`: nothing in it is secret; the pot odds are the numbers the info screen should state). A knob edit shows on the next state; the client engine copy stays the fallback.
- `daily.next` (in every state view: `g:coldcall:state` `pull.play|chips`, result `pull.state`, pending `pull.state`) = leads the next claim grants, taken from a dry run of the engine's own claim, never a copy of the formula. Unclaimed today: today's claim. Claimed today: TOMORROW's claim with the streak continued (a player who skips a day gets the base amount instead; it shows once `claimed` is false again). Per currency. `null` only if the probe cannot run (pull off). A pending Callback spin claims nothing, so `next` is for the first paid spin after it.

## FIX POT-CAP (2026-10-06, levers builder, LEVERS.md 8.11)
- Rule: a pot hit pays `min(bal, capCents)`, one cap in money for every bet. `CFG.pull.pot.capCents` = 5000 ($50 / 5,000 chips); `maxPayX` is gone. Code: `Eng.potPrize(pullCfg, bal)` in `games/coldcall-engine.js` (public copy byte-identical), called by `games/coldcall.js` settle() and by `games/coldcall-sim.js`. A `capCents` that is not a finite number >= 0 (NaN, text, negative, Infinity, missing) falls back to 5000, floored to whole cents; the prize is never above the balance, so fed + seeded = paid + bal still holds to the cent. Rules for moving the knob: `capCents >= feedBps x oneInPerDollar / 100` (3000) or the pot cannot pay out what it is fed; a chaser's pot EV is at most `capCents / 100 / oneInPerDollar` (1.67 points at 5000, chaser total 98.69, 0.013 under the 98.7 bar).
- Why: on `maxPayX` 50 x bet a 10c bettor could take $5 of a pot fed 1% of every bet (flat 10c 97.19, 20c 97.35, the pile-up went to the pot) and a $25 bettor could take $1,250 (a chaser got 41.7 points of pot, total 138.7). Now flat 97.98 / 98.00 / 98.02 / 98.02 at 10c / 20c / $1 / $25.
- Sim: new `--pot-room` mode (pot only, shared pot, feeders + one chaser); a one-feeder room reproduces `--pull`'s pot part bit for bit.
- Tests: engine `FIX POT-CAP potPrize` (incl. 200k scripted spins at mixed bets, seed 0 and 700, conservation), server `FIX POT-CAP` (10c hit on a $40 pot pays the cap at every bet, never above the balance, damaged knob settles at the default cap, 4k spins through the server). Re-pinned: `tests/lib-pull-pin.js` pot `maxPayX: 10000` -> `capCents: 1000000` (the pin means "no cap in play"; the pin also exports `real`, the live CFG.pull before pinning); the pot test that set `maxPayX = 3` now sets `capCents = 300` (same 300-cent prize at bet 100, but the cap no longer scales with the bet); the `rules` copy test edits `capCents`.
